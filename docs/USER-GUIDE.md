# gen-chibi user guide

**English** | [Tiếng Việt](HUONG-DAN.md)

> gen-chibi is a **factory for themed chibi assets**: build characters, items and scenes from one core frame → store them in the Library by theme project → publish them as **sale bundles**. **Making films** with the AI director is how the assets get used — and a live demo of the Library.

## Fastest: see the whole flow in 10 seconds
1. Open gen-chibi (default `http://localhost:7480`).
2. On the **Choose a workspace** screen, click **✨ Open the sample project "Fun Office"**.
3. You land in the **Library**: 3 characters, 1 item and 2 scenes from the sample project.
4. Open **Create** → the works table → click the row *Ngày đầu đi làm* (First day at work, 4 shots) to enter its **film room** → **Review** tab → **▶ Whole film**.
5. Go to the **Publish** tab → **Film (HTML)** to download the film — open the file in any browser to watch it, and send it to your viewers.

To see a **complete theme set** (what gen-chibi is built to sell): click **🏯 Open the sample theme set "Three Kingdoms"** — 7 generals (Peking-opera masks, weapons, 8 directions, their own voices), 13 pieces of equipment, 8 scenes and the film *Từ vườn đào tới Xích Bích* (From the Peach Garden to Red Cliffs: 6 shots with staging, voices, sound and a fight scene). This is a **Gen Labs sample set**: view it, try edits, make films freely, but it **cannot be exported as a sale bundle** — to sell, build your own set in a separate project.

The interface is in English by default; to switch to Vietnamese see [README › Language](../README.md#language) (`--lang vi` at install time, `genchibi lang vi`, or the language switch in the Studio).

## Three areas — three separate apps

| Area | Address | What it does |
|---|---|---|
| **Workshop** (amber) | `/xuong` | **Core frame** (theme-neutral, kept by Gen Labs), **New asset** from the frame, editors for characters / items / scenes |
| **Library** (blue) | `/thu-vien` | Assets that passed the gates, **organised by theme project** — view, download images / sprites, copy code, download / import project bundles; plus **Motions**, **Sounds**, **Voices** (tables, listen right away) |
| **Create** (green) | `/tao-tac` | **Works**: works table → a **film room** for each work (script · shots · review · voice & sound · publish) |

One-way flow: **Workshop → Library → Create**. The area switcher is always at the top left.

## AI assistant — one dock in the right-hand column, in every area
Everything you ask the AI for (creating assets, explaining the skeleton, finding / combining assets, making films) happens in **one chatroom in the right-hand column** (380 px wide by default) — there is no separate chat page. It needs an **LLM API key** in *AI settings*; without one the dock still shows, with a reminder and an **Open AI settings** button.
- **Collapse / open**: the **AI assistant** button at the top right or **Alt+J**; **drag the left edge** of the dock (or press ← → while the edge is focused, hold Shift for big steps) to change its width. Your machine remembers the state + width. On screens narrower than 1100 px the dock becomes a **drawer** over the right side.
- **Its role follows the area**: *Workshop* → workshop staff (create / edit assets from the frame) · *Core frame* → explains the frame, creates assets from the frame, builds **motion / pose packs** on the skeleton (never edits the original frame) · *Library* → librarian (finds, views, combines **existing** assets; the server refuses to create new assets from scratch here — ask for one and the AI invites you to the Workshop with an **Open Workshop** button) · *Create* → **AI director** of the open work. Same chat, same pinning / spotlight; the tool set and instructions change with the area (all through the same gates as MCP agents).
- **Viewing**: the top bar of the dock shows *Area › Page › object* (e.g. *Create › Shots › Từ vườn đào tới Xích Bích*) and the AI knows exactly where you are. Click **×** to drop the context (the AI then only knows the open area).
- **Pin (you → AI)**: type **@** in the input → fuzzy search (accents optional: `@luubi` finds *Lưu Bị*) → pick to insert a chip; or click **⌖ Point at screen** / **Alt+P**: hover a card, row, shot, step… → dashed outline + label → click to pin (**Shift+click** pins several, **Esc** exits). The AI only receives what is pinned (a snapshot trimmed to a budget); the input shows an estimate of **~N tokens** for the first round (typed text + pins + area instructions + interface data + history), and **under each answer the real token count** (in / out, summed over every tool round). The context sent to the AI is capped (≈ 24 thousand characters per round; review notes, shot lists and pins are all trimmed with a "trimmed" mark), so long works do not make messages more expensive. Every important element has an address by real ID: `asset:` · `item:` · `scene:` · `action:` · `work:` · `shot:<work>/<shot>` · `step:<work>/<shot>/<step number>` · `project:`.
- **Spotlight (AI → you)**: in an answer, everything the AI mentions is a **button**: *hover* → the element is highlighted (the rest dims); *click* → go to the exact spot (even in another area) + highlight for 2 seconds. Things the AI just created / edited (characters, shots…) become buttons automatically; an element that no longer exists shows **"gone"**. With reduced motion turned on in the operating system, only a static outline remains.
- **History per object**: each work / character / project has its own chat thread, stored on the server (`data/chats/`, up to 60 messages) — reopen it and it is still there, switch objects and the thread switches too. **Clear thread** at the top of the dock.
- **Trust boundary**: names, scripts, review notes and pinned snapshots are **data** — they travel in a separate message framed as JSON "not instructions", never inside the system instructions. The AI in the dock **cannot delete shots or reviews** (you do that yourself in the Shots tab); each thread and each work runs one AI turn at a time (two tabs / two threads writing the same film: the later one is told to "wait until it finishes, then send again").
- **Proposed edits awaiting review** (Create): when you have not said "just do it", the AI does not write the shot description / step list directly but **proposes** it — the *Shots* tab shows a diff (added words / lines in green, removed in red) with **Apply** / **Discard**.

## 1. Create a theme project (Library)
**Library › Theme projects › New project** — give it a name (e.g. "Three Kingdoms", "Vietnamese fairy tales"). Every asset and work belongs to one project; the Studio remembers the project you used last.

## 2. Create an asset from the frame (Workshop › New asset)
Four steps on one page:
1. **Pick a frame** — Character (mannequin), Item (10 blocks by shape: long stick, short stick, disc, box, sphere, hat, garment, cape, shoes, face cover), Scene (outdoor / indoor stage). Pick the project to save into.
2. **Parameters & details** — name, the part for each slot, length / size, palette, eyes / brows, identity marks, personality (items: type, rarity, stats; scenes: backdrop layers, time, weather, colours).
3. **Review every angle** — characters in 8 directions + 4 activities; items as icon + card + worn by the mannequin; scenes by day / night / with actors.
4. **Gates & save** — ✓ passed, ✗ blocked (must be fixed), ⚠ only required for **Published** (the draft is still saved and usable).

After saving: **+ Create another** (same frame, same project) · **View in Library** · **Make a film with this project**.
The frame is never modified — your asset is a copy of the frame + your parameters.

## 3. Make films (Create › Works)
**Works table** (Data Console): columns *ID · Name · Project · Shots · Approved · AI voice · Updated · Status*; search, filter by project / status; **New work** (name + project). Click a row to enter that work's **film room** — the address carries its id (`/tao-tac#/tac-pham/<id>/<tab>`) — you can bookmark it, but it only opens on the machine that has that install (it cannot be sent to someone else; to share, export a project bundle). **The AI assistant in the right-hand column is always the AI director of the open work**, and knows which tab and which shot you are on.
The room has 5 tabs:
1. **Script** — logline, overall script, **cast** (every actor in the shots, voice role, locked AI voice), **film language**.
2. **Shots** — one card per shot: **first-frame image**, name, description, scene, cast, number of steps, **estimated duration**, *View steps* (opens the step list), **Step table**, *AI writes dialogue*, *Rehearse*, *Ask AI* (pins the shot into the dock). Everything the AI director writes shows up here; proposed edits not yet applied show a **diff** with Apply / Discard.
3. **Review** — the stage: **▶ Whole film** and **▶ Shot** on each row; each shot has a status **Draft / Needs changes / Approved** + **review notes** (on the whole shot or on one step), saved in the work (`work.review`) through the server's gate; **Send to AI to fix per notes** pins the shot + step into the dock and pre-writes the request. The **Approved x/y** count shows at the top of the room and in the works table. A shot edited after "Approved" goes back to "Draft". **Only you set "Approved"** (in the Studio): the AI in the right-hand column and agents over MCP / link can only set Draft / Needs changes and **add** notes (labelled AI / agent) — the server enforces this, it is not just an instruction; the AI also cannot delete or edit your notes. Agents read review notes via MCP `get_work › review`.
4. **Voice & sound** — language + accent, **AI dub**, **ONE "Locked voices by character" table** and the **Sound** box: the S1–S7 mixing-rule results for the whole work (errors / warnings, click to go to the shot). The locked-voice table is **the only place to lock voices for a work**: one row per character → **voice role** → **locked voice** (`work.voices`) · **source** (*Locked* / *Picked by hand* / *Not locked*) · accent · number of lines · sample line, **▶ machine voice** (free) and **▶ AI** using exactly the locked voice (an existing clip plays for free; otherwise click twice, it uses 1 request); without a locked voice the AI button is greyed out. The **Lock voices for the whole cast (free)** button asks the server to choose voices for the whole cast and lock them into the work (no line is read). The table follows the **film language** in the box above; click a row to see its details in the panel on the right. To listen to / design the set of 22 roles: the **Role voice set ›** button → *Library › Voices*.
5. **Publish** — **Film (HTML)**, Storyboard SVG / PNG, JSON, project bundle.

Details of each part:
- **New work**: give it a name, pick a project.
- **Loose scripts**: an outside agent sends a script over MCP (`save_event`) → it shows in the *Loose scripts* box → **+ Make it a shot**.
- **AI director** (the dock on the right; needs an API key in *AI settings*): describe an idea or use the quick buttons *Write script · Split into shots · Write dialogue · Fix per review notes · Check for gaps*. The AI only uses assets in the Library; **when a character / scene is missing, the AI goes into the Workshop and creates it** (in the right project, through the gates) before using it. Every answer comes with a log of what the AI did (✓ / ✗).
- **It works without AI too**: add shots yourself, pick a scene, click to choose actors (≤ 8), then use *AI writes dialogue* per shot or edit the JSON over MCP.
- **Step table** (no AI needed): on each shot click **Step table** → a spreadsheet-style table, one row per step (`B01`…, up to 12): actor, expression, line, speaking to, spot, **action**, opponent, reaction, hold time.
  - Every dropdown comes from the director schema — you cannot type a wrong name. The **Action** cell only lists the moves that row's actor can perform (an unarmed actor does not see "Straight thrust"), labelled *attack* / *throw* / *needs weapon*.
  - The **Opponent** cell only opens once you pick an attack (it suggests someone); **Reaction** only once there is an opponent. The **more…** cell opens extra fields: camera, bubble, activity, view angle, facing, pose, movement, arm motion, effects (≤ 3), sounds (≤ 3).
  - Errors show right next to the row; **Save steps** is locked while errors remain and goes through the same gate as the AI / MCP. Closing the table without saving discards your changes (it asks first; closing the browser tab / reloading the page also asks). Edits made while a save is running still show *Unsaved*. Clicking outside the table closes it, but selecting text and releasing the mouse outside does not; **Esc** closes the table, **Tab** cycles within it.
- **Status**: the "Ready x/y shots" bar + a list of what each shot still lacks — click to go to that shot.
- **Review**: ▶ Whole film — the film has **automatic staging**:
  - characters **walk on stage**, **walk to a new spot** when the script changes their spot, **step forward** when angry / swearing / pleading and **step back** when shocked / panicking;
  - the speaker **turns to the listener** and gestures while talking; listeners nod, and flinch when shouted at;
  - the **camera** closes in on the speaker, frames two people in a dialogue, pushes in + shakes on a shout, flashes white on a shock;
  - **lip-sync** with the line; **dialogue** laid out cleanly, as in a film: comic speech bubbles — say, **shout** (small jagged edge), **think** (cloud), whisper (dashed edge) — with a name tag in the character's colour inside the bubble, a single typeface (Be Vietnam Pro, correct Vietnamese diacritics on every machine, embedded so an exported film still renders correctly offline), text readable at once, and a soft highlight on the word being spoken;
  - **bubbles never cover anyone's face**: for each line the player measures where every actor's head is in the frame (even during a close-up) and picks a spot that does not overlap a head — above the head, beside it, a corner of the frame — close to the speaker's mouth; the tail points towards the mouth but stops short of the face and never cuts across another person's head. When the same person speaks several times in a row, the bubble keeps its place instead of jumping. When a close-up is too tight to leave a clear spot, that line becomes a **lower-third subtitle** (name tag in the character's colour + white text on a dim dark band);
  - the **Dialogue** box next to the sound controls (Review tab): *auto* (a bubble when there is a clear spot, otherwise a subtitle — the default) · *bubble* (always bubbles) · *subtitle* (always subtitles, good for fast reading or screen recording). Remembered per machine; **an exported HTML film carries the selected style** as its default, and viewers can change it with the box of the same name on the control bar. With "reduce motion" turned on in the operating system, bubbles do not bounce;
  - **sound**: effects by emotion / action, ambience by scene (birds, crickets, rain, wind), light music by mood, **a voice for each character**.
  - The 🔊 button turns sound on / off; voice choices: *auto* (the dubbed AI voice when there is one, otherwise the browser voice in the role's language + gender, otherwise blips), *Google AI* (reads with the AI voice live while playing — uses requests), *machine voice*, *game-style blips*, *off*. The **Sound** box (sound on / off, voice style, dialogue style) sits next to the stage in the *Review* tab; **Language · Accent · Dub** are in the *Voice & sound* tab; **Export** is in the *Publish* tab. See **AI voices by role** just below.
  - For finer direction: each line can set `to` (who it is said to), `camera` (close / two / wide), `bubble` (say / shout / think / whisper), `sfx`; the AI director knows these fields. Change `spot` between lines to make characters move around.
  - **Action & fights**: a script step can be a piece of choreography — `action` + `target` (who gets hit) + `react` (`hit` hit, `fall` flips over then springs back up, `ko` knocked out, `block` parry, `dodge` back-flip dodge).
    - **Frame moves** (anyone can use them): `punch` (to the face), `kick`, `push` (face push), `throw` (throws a tomato from afar); with a weapon in hand: `thrust`, `sweep`; solo: `rage`, `hero`, `victory`, `dance`, `salute`, `wave`, `stretch`, `scratch`, `startle`, `flip`.
    - **Motion-pack moves** in the project (e.g. the Tam Quốc set: `combo` combo strikes, `spin` spinning slash, `leap` leaping chop, `twirl` spear twirl).
    - A character **has a weapon** when the right hand holds equipment of type *Weapon* (or a part that declares `grip: weapon`). Without one, weapon moves are blocked, with a suggestion of moves that work; fans, books… are props.
    - The attacker closes in / backs off automatically so the move lands; two heads never overlap; nobody flips or flies onto bystanders; the opponent reacts on the exact impact frame. Set `say` to `""` for a move without a line.
    - Write them with the **AI director**, over MCP, or right in the Studio with the **Step table** (above). The **Ready** bar warns when a move does not exist (missing motion pack) or the actor cannot perform it.
    - Machine still has the old Tam Quốc set? In **Library › Theme projects**, click **⟳ Update Three Kingdoms sample** to import the new version (with its motion pack).

### AI voices by role
Voices follow the **role** (age · gender · scholar / warrior · noble · comic · villain · narrator — 22 roles, including old man, old woman, little boy, little girl, warrior general, strategist…) for **Vietnamese** (Northern / Southern / Central), **English** (US / UK), **Chinese** (Mandarin / Taiwan) and **Cantonese** (Hong Kong). Note: genuine regional accents (Northern / Central / Southern Vietnamese, Taiwan) **only come from Voice design** — see the *Real accents* bullet below.
- **Paste a key and it works**: *AI settings › AI voice (Google Gemini)* — paste a Google AI Studio key into the single field and click **Connect**; the machine checks the key (free) and **turns itself on**. If you already pasted a Gemini key for the AI director, it works right away without pasting again. The key stays on the server only and is never shown again in the browser. There is a **Turn off / Turn on** button. This page **only holds settings**: the key, Turn off / Turn on, *Daily line cap*, temporarily failed voices (the *Retry failed voices* button), the number of lines used today (status line) and the link **View role voice set → Library › Voices** — the 22-role table no longer lives here.
- **Role voice set** — only in **Library › Voices** (see *Voices — view, listen, design voices by role* below): a table of the 22 roles for the chosen language + accent — the voice in use and its source (*designed* / *Google library* / *built-in*), **▶** plays the machine voice (free), **AI** plays a sample line with the AI voice (**uses 1 request** if there is no clip yet), **Design voice** (~25 seconds, **uses 1 request**; redo with *Redesign*). **Child roles** (little boy, little girl, boy, girl) **cannot be designed** — Google blocks child voices; use the youthful built-in voices. An accent only takes effect for roles that have been through *Voice design*; not designed = the language's generic voice.
- **Each character**: *Library › Characters › Voice* — voice role ("Auto-guess" if none is chosen), accent, AI voice (once a key is set), pitch + speed. **Save voice** only stores pitch / speed if you moved them.
- **Film language** (the *Language* box in the Voice & sound tab — or *Dialogue language* in the Script tab; saved in the work. A new work starts in the interface language it was created in — English Studio, English film; a work an agent creates follows the machine default; works made before v0.20 are Vietnamese): machine voice, AI voice and dubbing read in this language — dialogue must be written in that language (Cantonese: Traditional characters + colloquial words such as 喺 / 咩 / 我哋, not written Mandarin). Each character gets a different AI voice.
- **Character voices are locked per work**: the first time the machine picks AI voices for a work's cast (by language + accent), those voices are **locked** into the work — the Studio, agents (MCP `render_voice` with `work`) and the exported film all use the same voice. Adding a new actor, or Google adding new voices, **does not change** existing actors' voices; a voice only changes when you choose to (Voice design for a role, or picking an AI voice in the Character profile). View and lock them in the work's room › **Voice & sound** tab › *Locked voices by character* table (button **Lock voices for the whole cast (free)**). One work picks AI voices for at most **48 actors**; the rest have no AI voice yet — the Studio shows a line "N actors beyond 48 have no AI voice" in the *Dub* block, and their lines use the machine voice.
- **Real accents only through Voice design**: Google only gives genuine Northern / Central / Southern Vietnamese, Taiwanese… accents when you *Design voice* for each role (1 request per role, ~25 seconds); built-in voices and Google's Vietnamese voice library **do not distinguish** Northern / Central / Southern, so they read with a generic accent (only *UK English* has a voice library of its own). In the **Voice & sound** tab, the *Accent* line (under the Language box) shows **"accent available for N/M roles (designed)"** — M is the number of distinct roles in the work's cast (child roles are not counted because they cannot be designed), N is the number of roles designed for the film's language + accent. The **Design accent voices for the roles** button designs all the missing roles in one go: clicking it shows an in-page confirmation box with the number of roles ≈ number of Google requests and ~25 seconds per role; nothing runs until you click *Start designing* — then it goes role by role, with a progress bar and a *Stop designing* button; when the quota runs out (or the daily cap is reached) it stops exactly there and tells you when to retry; when done, the voices of the whole cast are chosen again. gen-chibi never designs voices silently.
- **Daily line cap** (AI settings › AI voice): the *Daily line cap* field — default **200**, `0` = unlimited, maximum 5000. Once the cap is reached the server reads no new lines (and designs no more voices) until 00:00 the next day, and every path through the server is blocked; the Studio says **"Reached the cap of N lines today (AI settings)"** — different from "Quota used up today" (Google's quota) and "Google per-minute limit". Lines already read still replay for free. The status line shows **"today N / line cap"**. The cap keeps cost within reach if your Google project has billing turned on.
- **Temporarily failed voices**: when Google reports that one specific voice cannot be used, gen-chibi avoids that voice for **24 hours** and then tries it again (built-in voices are not marked, since that is a general Google error). AI settings shows **"M voices temporarily failed (retried automatically after 24 h)"** with a **Retry failed voices** button to retry now; reconnecting the key also clears the marks.
- **AI dub** (Voice & sound tab): reads every line in turn and **saves** them ("AI dub 7/31"); lines already read are fast and use no request. When Google hits its **per-minute limit** (retry time ≤ 2 minutes away) it **does not stop**: it shows "Google per-minute limit — dubbing resumes at HH:MM:SS", waits, then reads that same line (at most 10 waits per click; **Stop dubbing** cancels even while waiting). **Quota used up today** (or the daily line cap reached) stops it and shows the retry time + the number of lines done — click again later to continue. Without a key: the button is greyed out, with a shortcut to *AI settings*.
- **Playback and export**: the *auto* voice style only uses AI voices **already dubbed** (no request); *Google AI* reads live while playing. A **Film (HTML)** embeds the AI voices of the dubbed lines (toast "N/M lines with AI voice" + file size) and, opened via `file://`, makes no network calls — if some lines have no AI voice yet, clicking **Film (HTML)** asks first: **Dub, then export** · **Export now** (missing lines read by the machine voice / blips) · **Cancel**. A film without all its clips shows the label **"AI voice 19/31"** next to the Voice box. The film page's language tag (`<html lang>`) follows the film language (vi · en · zh-CN · zh-TW · zh-HK).
- **Google's free tier has very few requests per day** (a few dozen lines); lines already read are cached, so they do not cost again. Turning on billing in Google AI Studio is the owner's decision — gen-chibi never turns it on by itself.
- **Browser voice fallback**: with no key, no quota left, AI voice turned off or a broken clip, the film still plays with the browser's built-in voice, in the role's language + gender (no voice for that language → blips, never reading in the wrong language). Machine voices come in two grades — **basic** (espeak, old Microsoft voices, macOS novelty voices…) and **good** (all the others: Edge "Online / Natural", Google, Apple Linh, Google TTS on Android…). A film that already has AI voices sounds choppy with a robot reading in between, so in the *auto* voice style lines without a clip are only read by a **good** machine voice, otherwise blips; choosing *Machine voice* outright does not filter by grade. If the machine voice gets stuck (no sound after ~1.5 seconds) it retries once — if the browser says it is still loading voices it waits up to 4 seconds — and if it still fails it switches to blips, trying the machine voice again only after 30 seconds (in every voice style); "…" and "—" are turned into commas when handed to the machine voice (the on-screen text stays as it is).

## 4. Draft, Published and project bundles — back up, move machines, sell themed asset sets
Each asset has one of two statuses:

| Status | Meaning | Who sets it |
|---|---|---|
| **Draft** | Usable right away in the project (acting, films, image export). No identity marks needed | Default — every new asset, including those the AI creates |
| **Published** | Good enough to **sell / share**: goes into the project's *Sale bundle*. Characters need identity marks (the gate warns if they are missing) | You, by clicking **Publish** in the asset's *Use* panel in the Library (click **Back to draft** to withdraw) |

In **Library › Theme projects**, pick a project:
- **Backup bundle (JSON)** — every asset (drafts included) + the custom parts / backdrops in use + **works** + the motion packs the films use (even those of other projects). For backups and moving machines.
- **Sale bundle · N published assets** — only **Published** assets, **no** works. If a published asset needs something still in draft (e.g. a character holding a draft item), the bundle still pulls it in to be complete and **shows a warning** — publish that item too before selling.
- **Import bundle…** — every entry goes through the same gate as when it was created. On a duplicate id it asks whether to overwrite — overwriting creates a **new version**, the old one stays in history. A bundle declares the libraries it needs (`requires.packs`); missing ones are reported clearly.

### Character voices
Library › Characters › **Use** panel › **Voice**: pick a **voice role** and accent, drag pitch (low ↔ high) and speed (slow ↔ fast), click **▶ Preview**, then **Save voice** to use it in every film. If nothing is set, gen-chibi guesses the role (generals / bosses lower, soldiers / kids higher). AI voice details: **AI voices by role** in the film section.

## 5. Use assets elsewhere
In the Library, each asset has a **Use** panel: download SVG / PNG / avatar / expression sprite / **8-direction sprite**, copy the reference code, MCP call code, web embed code, recipe JSON.
Reference codes look like `<library>/<id>`: the core frame is `gen.khung/…` and `gen.core/…`, your assets are `local.my/…`. The old names `afi.khung/…`, `afi.core/…` (before v0.12) still load and are renamed automatically on save.

### Motions — preview and download the animation of one move
**Library › Motions** lists the frame's moves and those of each **motion pack** (by project, labelled Draft / Published / Sample).
- Pick a move → pick the **attacker** (characters that cannot do it are greyed out with the reason — e.g. *— needs a weapon* for `thrust`; if the one already selected cannot do it, it says why and does not render), the **opponent** and the **reaction** → instant preview, pause / play, 8 · 12 · 24 frames per second.
  - When a long move (e.g. a custom pack with a clip of several seconds) needs more frames than allowed (120), the Studio **lowers the fps automatically** to fit the whole move and says *"lowered to N fps automatically"*; GIF / JSON use that real fps. If even 4 fps is not enough, a warning says *the end is cut off* — shorten the clip.
- **Download the animation**: **PNG sprite sheet**, **GIF** (loops forever, transparent background), **SVG sheet** (vector), **JSON timeline** (`gen-chibi.anim/1`: fps, frame count, impact frame, coordinates of each frame in the sheet). Pick the **Frame size for download**. A fixed frame encloses the whole move, so frames never jump in size — usable directly in games, on the web, as chat stickers.
- **Download pack (.json)** / **Import motion pack (.json)**: packs go through the gate (errors listed in full). The **Import into project** box (next to the import button; defaults to the project you just used) decides which project the new pack belongs to — leave it at *No project* to keep the project written in the file; if the file has none, the pack is a **shared pack**, usable with any cast. Motion packs are also part of a project's backup / sale bundles; packs from Gen Labs samples are not for sale (files downloaded from a sample carry the `sample` mark, and animation JSON states the sample licence: viewing, trying and filming only).
- Agents: the same via MCP `render_action` (see `agent/workflows/animation.md`).

### Sound — a reusable library of cartoon effects
Sound in films is a **library** (not audio files): every sound is a **synthesis recipe** in code — exaggerated like a cartoon (BONK, BOING, ZIP, WHAM, SPLAT, TA-DA…): big pitch jumps, musical notes, wobbly tails, slightly "toy-like". Lightweight, no third-party copyright, and it works even when the HTML film is opened via `file://`.
- **The standard set** (62 sounds, 8 groups: *Impacts & hits · Movement · Comedy · Emotion & accents · Magic & energy · Nature · Objects & bells · Effect instruments*) is available in every project. 17 old sound names (pop, whoosh, step, sting, hit, boing…) still work, they just sound different — old scripts need no changes.
- **Project sound packs**: each theme project adds its own sounds (the Tam Quốc sample: *war drum, horn, hoofbeats, ancient sword, arrow volley, horse neigh, arrow shot*). A project's sounds can only be used in that project. Sound packs **travel with project bundles** (backup, import, sale bundle — including the packs a work or motion pack calls by name, even shared ones / those of another project; a sale bundle warns if such a pack is still a draft) and **with exported HTML films**. Rules: at most 32 sound packs per project (the same cap as on import, so any backup can be imported again) · a pack **without a project** is a *shared* pack — it adds sounds callable from any project but **has no cues** (it cannot change the frame's auto-assigned sounds) · removing a sound that is still called, or changing the project of a pack that is still called, reports a conflict with the list of every caller (only the owner can force it) · through an MCP link / the AI chatroom a pack must belong to a project and cannot overwrite another project's pack · **removing a pack**: `DELETE /api/sound-packs/<id>` or MCP `delete_sound_pack` (owner only; if it is still called it reports a conflict; the file goes to the trash).
- Each sound has a label, tags, a duration and a **"use when"** line. **Library › Sounds** (described just below): filter by group / tag / text / project, **▶ preview**, **download WAV** (a single sound or a multi-sound "recipe") to use elsewhere.
- **Assigning sounds in a film**: most steps **need no choice at all** — the player auto-assigns up to 2 sounds by expression / effect / activity (the project's pack wins over the standard set; epic or comic shots may change the pick). Only choose by hand in the Step table (**more… › Sounds**, up to 3) when you want to **accent** a moment; choose `[]` (no sound) to keep a step silent. **Attacks** need nothing — the impact sound plays exactly on the hit.
- **Mixing rules** (the Studio and agents check the same rule set, in `engine/sounds.js`): an **error** blocks saving, a **warning** still saves and is reported back.
  | Rule | Level | Content (translation of `GC.sounds.RULES`; the Vietnamese originals are verbatim in [HUONG-DAN.md](HUONG-DAN.md), where test 2n guards them) |
  |---|---|---|
  | **S1** | error | ≤ 3 sounds per step; ≤ 1 ACCENT sound (group cam-xuc / nhac-cu) per step — two accents at once cancel each other out. |
  | **S2** | warning | Density ≤ 4 sounds within 2 seconds of film (including auto-assigned sounds and the dialogue-bubble pop, not counting step / tick) — denser is "noise", the audience loses the accent. |
  | **S3** | warning | An accent sound must not cover a line: put it on a step without dialogue, or pick a short sound that ends ≥ 0.3 s before the line. |
  | **S4** | warning | Leave impact sounds (group danh) to the move, which plays them on the hit; place one by hand only on a step with a visible impact (attack, thrust, defend, kowtow, faint, jump, injured, dizzy). |
  | **S5** | warning | The same sound on at most 3 consecutive steps (except step / tick) — switch to another sound of the group or drop it. |
  | **S6** | error | A sound must exist in the project's library (frame + shared packs + the project's packs) — an unknown name / another project's sound is an error, with the nearest name suggested. |
  | **S7** | warning | Long sounds > 2 s (gong, dun-dun, war drum…) only on the first / last step of a shot (opening, transition). |
- **Sample recipes** (build-up → impact → consequence, one sound per step): *tiptoe → step on a banana peel → slip and fall → splat → sad* (`tiptoe → slip → slide-down → splat → sad`) · *wind-up → WHAM → fall → birds circling* · *bright idea → dash away* · *power up → transform → ta-da* · *honk → ba-dum-tss*. The full list is in Library › Sounds.
- **Add your own sounds**: ask an agent (MCP `get_sound_spec` → `validate_sound_pack` → `save_sound_pack`, see `agent/workflows/sound.md`) or import a `gen-chibi.sound/1` pack (.json). Packs go through the gate: only numbers + strings from the allow-list (no code), at most 60 Web Audio nodes per sound. Sound names are **global across the library** — a duplicate name reports which pack already holds it. Listen before you keep a sound: agents cannot hear, they only check with the gate.

#### Library › Sounds — table, mixing rules, packs
A Data Console style table (desktop): one row per sound — **sound ID** (the name used in `step.sfx`), label, group, duration, **"use when"**, tags, pack (*Frame* / pack name), project, **auto-assigned cue**. The table has **3 tabs**:
- **Sounds** — 8 group filters (with counts), an **accent-insensitive search** box (name, label, tags, the "use when" line — Vietnamese words match without their diacritics), filters for **tag** / **pack** / **project** (only shows the sounds that project can use — exactly rule S6), click a column header to sort.
  - **▶ play right on the row**; keyboard: `↑` `↓` (or `J` `K`) change row, `Space` plays the selected row, `/` jumps to search, `Esc` clears the search.
  - **Inspector on the right** (400 px): play, **Download WAV**, **Copy name**, "use when", tags (click to filter), auto-assigned cue, and a **Use in a script** box: *Script step (JSON)* — a step `{ actor, state, say | hold, sfx: ["name"] }` ready to copy and paste (put **accent** sounds on a step without dialogue) — and *MCP call* (`lint_sound_track` with `project` + how to look things up with `list_sounds` / `get_sound_pack`).
- **Mixing rules** — the only place in the Studio that explains **how to mix sounds**, taken straight from the engine (`GC.sounds.RULES`, `RECIPES`, `guide()`) so it always matches what agents see: the **5-step workflow**, the **seven rules S1–S7** (level *Error* blocks saving / *Warning* only reminds), the **sample recipes** — each with **▶ Play sequence**, **Download WAV**, **Copy steps** (an array of script steps) — and a **Try the rules** box: paste JSON steps, pick a project, click **Check S1–S7** to see errors / warnings with their position, like `lint_sound_track`.
- **Sound packs** — the list of packs (ID, name, project, version, number of sounds, status), **Download JSON** (user / sample packs), **View sounds** of a pack, **Remove pack** (only user packs saved on this machine — the frame pack `gen.am` and sample packs have no button; you must click **twice** to remove). If the pack is still called somewhere (script steps, motion packs…), the server refuses and the Studio shows the **list of callers** with **Remove anyway** (those callers will then report S6 errors / lose the sound on load) or **Keep pack**; an older server without the remove feature says "This server does not support removing packs yet". **Import pack**: choose a `.json` file or paste JSON → **Check pack (no save)** → **Import into library** (pick a project). Gate errors show **with their path** (e.g. `sounds.am-hong.layers[0].hz: out of range…`); a sound name already used by another pack is blocked immediately. The preview edition without a server can only check, not save.

**Sound mixing workflow for people and agents** (one rule set): ① leave `sfx` empty on most steps — the player auto-assigns ≤ 2 sounds by cue; ② set `sfx` only to **accent** something (≤ 3 sounds, ≤ 1 accent, accents on steps without dialogue); ③ use `action` for impacts, never place them by hand; ④ comedy: "build-up → impact → consequence", one sound per step (see the recipes); ⑤ check S1–S7 (Mixing rules tab or `lint_sound_track`) before saving. Agents: `list_sounds` → `get_sound_spec` → `lint_sound_track` (see `agent/workflows/sound.md`).

## 6. For AI agents (MCP) — agents from any vendor can use it
- Run **`genchibi agent connect`**: prints ready-made connect configs for Claude Code, the Claude app, Cursor, Gemini CLI, Codex CLI and a `curl` command (it never prints the token).

If you already have your own `AGENTS.md` / `GEMINI.md`, the command stops and does not overwrite them (add `--force` to replace).
- Tell the agent: **"call `start_here` first"**. The agent receives the Library status, 11 golden rules, 10 guide topics (characters, parts, equipment, scenes, motion packs, sound, animation, film, project bundles, system), then follows step-by-step procedures with runnable examples.

### Connect claude.ai with one address, `https://your-domain/mcp` (OAuth, since v0.19)
The agent works out how to sign in and registers itself; all you do is click **Authorize** once on the app's web page. No key to copy, no token to paste into the agent.

1. **Set the public address.** In the install's `.env`, write `GC_PUBLIC_URL=https://your-domain`: exactly the address reachable from the Internet, no trailing `/`, no port. Add `GC_API_TOKEN` (required once exposed) and `GC_ALLOWED_HOSTS=your-domain`, then run `genchibi restart`. If you use `genchibi expose your-domain`, the command sets all three itself and opens exactly the routes needed through Cloudflare Tunnel. Installs that ran `expose` before v0.19: **run `genchibi expose your-domain` once more** so the tunnel also opens the OAuth routes.
2. **Running your own proxy (Caddy, nginx…)? Open the machine routes** — see *Behind a proxy and your own login page* below.
3. **Add the connector on claude.ai:** go to *Customize › Connectors › Add custom connector*, paste `https://your-domain/mcp`, click **Add**, then **Connect**. Leave *Advanced settings* empty: no Client ID / Secret, the app registers the client itself.
4. **Authorize.** The browser opens the app's **Authorize agent connection** page. Check the agent's name and **the address it will return to** (must be `claude.ai` or `claude.com`), pick a permission level, then click **Authorize**. If this browser is already signed in to the Studio, the page uses that token; if not, paste the owner token (`GC_API_TOKEN`) into the field on the page.
5. **Open a new session** on claude.ai or in Claude Code: the gen-chibi tools appear. A session that was already open does not load a new connector.

| Permission level | What the agent can do |
|---|---|
| **Read only** (`mcp:read`) | Read the library and works, check recipes, render preview images. Saves nothing. |
| **Create and edit** (`mcp:write`, default) | Create and edit characters, items, scenes and works in projects. Uses no AI-voice requests, cannot remove sound packs, cannot update the app or roll back (one step stricter than the old keyed link, which can still update the app). |
| **Full owner access** (`mcp:owner`) | Same as the owner token: add AI voices (uses requests), remove sound packs, update or roll back. Grant it only to agents you fully trust. |

- **Manage in Studio › System › Agent connections:** see which agents are connected, their permission level and last use. Click **Revoke** and the agent loses access immediately, refresh tokens included. To change the level, click **Change scope** on the agent's row (takes effect immediately).
- **Tokens:** valid for 1 hour and refreshed automatically. Unused for 30 days, they expire. The app only stores hashes, in `data/oauth.json`.
- **Claude Code CLI:** run `claude mcp add --transport http gen-chibi https://your-domain/mcp`, then type `/mcp` in Claude Code and choose **Authenticate**. The Authorize page opens in the browser.
- **The old keyed link** (`/mcp/<key>`) keeps working as before, for agents without OAuth support.

#### Behind a proxy and your own login page
claude.ai calls the routes below **from Anthropic's servers**, so it has none of your login cookies. These routes must go **straight** to the app, and they stay protected by the app's own OAuth tokens:

`/mcp` · `/.well-known/oauth-protected-resource…` · `/.well-known/oauth-authorization-server` · `/oauth/register` · `/oauth/token` · `/oauth/revoke`

If you have your own login page in front of the app (forward_auth, Authelia, basic auth…), put it **inside a `handle`**. Do not put it at site level: then it also runs for `/mcp`, Claude gets the login page (the gate's 302 / 401) instead of the app's "where to sign in" answer, and the connector reports that it cannot connect. The Authorize page (`/oauth/authorize`, `/api/oauth/approve`) can stay behind the login gate: you sign in first, then click Authorize; the app still asks for the owner token.

The full annotated sample is `docs/Caddyfile.oauth.example`. Short version:

```caddy
your-domain {
	@machine path /mcp /mcp/* /.well-known/oauth-protected-resource* /.well-known/oauth-authorization-server* /oauth/register /oauth/token /oauth/revoke
	handle @machine {
		reverse_proxy 127.0.0.1:7480
	}
	handle {
		# your own login gate (forward_auth …) goes here
		reverse_proxy 127.0.0.1:7480
	}
}
```

- **Network:** use port 443. The domain needs an A record (public IPv4). Do not redirect `your-domain` ↔ `www.your-domain`, because a redirect drops the `Authorization` header.
- **Cloudflare:** *Bot Fight Mode*, *Block AI bots* and *AI Crawl Control* return 403 to the `Claude-User` agent. Create a WAF **Skip** rule for Anthropic's IP range `160.79.104.0/21`, or turn those features off for the machine routes above.
- **Cloudflare + rate limiting:** the app rate-limits registrations / failed attempts by client IP. By default it only reads the last entry of `X-Forwarded-For` (and only when the connection to the app comes from loopback or a private network). Behind Cloudflare, add `GC_CLIENT_IP_HEADER=cf-connecting-ip` to `.env` (or `x-real-ip`) so the app sees the client's real IP instead of the proxy's.
- **Adding your own services to Docker** (Caddy, a login page…): put them in `docker-compose.override.yml` next to `docker-compose.yml`. Docker Compose merges the two files, and `genchibi update` never touches the override file.

## Frequently asked questions
- **Do assets the AI creates need approval?** No — they are saved as **drafts** in the work's project and usable right away. Only when you want them in a sale bundle do you click **Publish**.
- **Does a shared HTML film expose the engine?** The player sits in the film file under a licence **for viewing that film only**. A future SaaS edition will move to a player hosted by Gen Labs, or to video export.
- **Broke something?** Every asset and work has versions; old versions live in the data folder (`versions/`).
- **Clicking Update says the request from an unknown origin was blocked?** The server only accepts change commands from its own Studio page. The message (since v0.18.1) states *where the page is open* and *which address the server sees*: reopen the Studio at the server's exact address (usually `http://127.0.0.1:7480`), or update right away in a terminal with `genchibi update` (no browser involved). `localhost` / `127.0.0.1` / `[::1]` on the same port count as one; with a proxy in front, have the proxy send `X-Forwarded-Host` or set `GC_PUBLIC_URL`.
- **Adding the connector on claude.ai fails, or the Authorize page never shows?** Check in this order:
  1. `curl -i -X POST https://your-domain/mcp -H 'Content-Type: application/json' -d '{}'` must return **401** with `WWW-Authenticate: Bearer resource_metadata="…"`. If you get a login page, a 302 or a 403, the proxy or Cloudflare is blocking (see *Behind a proxy*).
  2. `curl https://your-domain/.well-known/oauth-authorization-server` must return JSON whose `issuer` is exactly `https://your-domain`.
  3. `GC_PUBLIC_URL` must match the address pasted into claude.ai **character for character**.

  If you change the address, delete the connector and add it again, because claude.ai caches the discovery result for about 5 minutes.
- **I have my own login page in front of the app (built by another agent) — will an update wipe it?** No, as long as it lives **outside** the install folder: a Caddyfile, a separate service, or `docker-compose.override.yml`. It will be lost if it was written into `docker-compose.yml` or into files under `current/`: on every update or start, genchibi copies the original `docker-compose.yml` back, and new versions are extracted into their own folder.
- **How do I switch the interface to Vietnamese?** For the whole install: `genchibi lang vi` (or `--lang vi` at install time). For yourself only: the language switch in the Studio. Details: [README › Language](../README.md#language).
- **Performance?** At most 8 live actors per stage; still images are cached; actors are destroyed when a shot ends.
